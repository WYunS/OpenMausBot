自动 Release 仅表示所选平台自动化门禁通过，不表示账号、TCC、Keychain 或真人业务已验收。


更新：2026-09-21。验收对象是公司企业内测最终安装包，不是源码版、开发快捷方式或独立 Harness。
先阅读 [Mac 打包指导](02-macOS打包指导.md) 和 [通用门禁](04-通用回归与发布门禁.md)。

## 0. 0.1.85 首次双包的验收准备

预先安排一台 Apple Silicon 和一台 Intel 原生 Mac，以及各自获授权的隔离测试账户。
每种 CPU 单独保存安装路径、进程架构、签名/包内依赖结果、DMG 哈希、权限和重启/升级记录。
两边可以共用测试清单和源码版本，不能共用一份“通过”回执；旧 Universal 的通过记录不继承。

自动构建通过不改变真人验收的“未执行”状态；收到已验证的两份 DMG 后再按本文逐项填写。
未拿到其中一种架构的包时，保留另一项未执行，不用 Rosetta 或 Windows 结果替代。


## 1. 收到包后，先固定对象

| 测试机器 | 应测试的文件 | 实际进程架构 |
| --- | --- | --- |
| Apple Silicon（M 系列） | `RuijieBot-<版本>-mac-arm64.dmg` | arm64 |
| Intel Mac | `RuijieBot-<版本>-mac-x64.dmg` | x64（lipo 显示 x86_64） |

两份包使用同一批次的 Bot 版本、最终构建源码 SHA，**各有自己的 DMG SHA-256**。
不再要求同一个 Universal DMG；Rosetta 测试只能作为附加结果，不能代替 Intel 原生机器。
如果只收到一种 CPU 的包，只能验该 CPU，不能签“Mac 双架构通过”。

向打包者取得：仓库、workflow/run、输入 source_ref、prepare 最终构建 SHA、toolkit SHA、
Bot 版本、两包哈希、BUILD-MANIFEST、自动检查结果、签名状态。
不要只凭文件名、版本号或某次 Actions 绿灯认定对象相同。
自动化的 candidate/pending artifact 与 verified release artifact 不同；来源不清先退回确认。

本企业 Mac 为 `ad-hoc signed, not notarized`，不具备 Developer ID 公证保证。
包内 Harness 固定 2.1.10 / f48fe5cb09e37c1bcb4ed2c19f75ce5e1bf8aeae；
用户**不需要另装 Harness**。实际 pin 以交付 manifest/共享源码 pin 为准，不能装一个外部 Harness 来掩盖缺失。

## 2. 测试环境和安装基线

使用获得授权的专用 Mac 系统账户；安装、覆盖升级、登录、系统权限均由测试者确认。
禁止复制开发者的 Keychain、SSO、飞书 token、浏览器 cookie、私有 profile 或真实聊天。
不要清空全局 TCC、卸载其他软件、结束其他用户进程或修改系统代理来强行通过。

1. 核对最终 DMG SHA-256，与打包者清单一致。挂载后按 Mac 指导复验架构、完整签名、资源及许可。
   不要求两套 native 目录；本轮使用本 CPU 的平面 `Contents/Resources`。
2. 将 App 安装到组织允许的固定 Applications 路径，从该安装位置启动；
   不从 DMG、下载临时目录、源码 Electron 或另一份旧 App 同时运行。
   记录实际可执行路径，兼容 Bundle ID 应为 `com.openmausbot.app`。
3. 使用没有开发 Node/pnpm、没有独立 Harness/CuaDriver 的环境作为新机基线。
   已安装这些工具的机器若另作补充测试，必须核对实际进程路径，不能借它们通过包内验收。
4. 记录 macOS 版本、CPU、签名类型、首次打开提示及组织安装策略。
   ad-hoc 未公证导致的 Gatekeeper 提示与包损坏/签名不完整分开报告；
   若组织不允许安装此类内测包，标环境/分发策略阻塞，不绕过策略。
5. 应用标题/登录页为锐捷Bot，Finder、DMG、Dock 图标正确；冷启动有加载反馈，
   不出现无说明的长时间黑屏，不无故弹独立 Harness GUI。
6. 完全退出后服务安全收尾，重开数据保留，不出现两份服务抢同一数据目录。

安装版服务数据为当前用户 `~/.ruijiebot`；开发版为 `~/.openmausbot`，
Electron Application Support 下的 userData 是另一层。不得合并、复制或用开发登录替代安装登录。

## 3. 默认电脑、CUA 和权限（两种 CPU 分别必测）

### 3.1 新建即默认“这台电脑”

1. 全新配置连续新建两个临时 Bot，都默认“这台电脑”，不自动选择云沙箱、不要求沙箱密钥。
2. 完全退出后重开，再建第三个 Bot，仍默认本机；用户明确选过其他电脑的旧 Bot 保持原选择。
3. 在临时文本编辑窗口实际截图、点击并输入无害文字，确认调用包内 CUA。
4. 仅移动鼠标、聚焦、放大/缩小不应误触人工接管；真实点击/滚轮/键盘操作后暂停，交还后可继续。
5. “没有电脑”模式普通问候也能回复；没有配置 VM/云电脑不能让普通聊天失败。

记录实际 CUA 的 embedded/standalone 模式及进程路径。
如果运行了独立 CuaDriver.app，只能算该模式结果，不能给包内 CUA 打勾。

### 3.2 TCC 稳定性与拒绝恢复

前提：固定安装路径、对应架构、只有本次测试 App 运行。
记录 `codesign -dr -`、签名类型、责任进程、完整弹窗文字与时间，不只截图设置页的开关。

1. 无操作冷启动不应无理由索要屏幕访问。主动使用电脑功能时，由人授予屏幕录制/辅助功能；
   按系统要求重启后，能得到真实画面并完成输入。
2. 同一版本连续截图/接管三次、停用再启用三次，不应对已经授予的同一权限每次重复申请。
3. 完全退出重开三次，每次实际截图；条件允许再注销/重启测试账户验证。
4. 在独立场景拒绝或取消一次：停止自动请求并说明原因，不能无界重试。
   用户在系统设置修正后主动重试能恢复；不自动点击系统许可。
5. 同版受保护目录访问也应按实际功能验证，不用“给全盘访问”代替屏幕录制或辅助功能。
6. 覆盖升级分签名类型记录：
   ad-hoc 跨版本可能改变身份并需要重新授权，须明确告知并在授权后重做同版稳定性；
   不将“升级后必须永远零弹窗”作为本企业候选的硬性要求。
   正式 Developer ID 路线另验稳定 requirement 和 Team，不继承本次内测结论。
7. macOS 自身周期性权限复核与每次操作循环分开记录。
   同版本每次截图/重开都弹、拒绝后无限弹、授权后仍无法使用，均为失败。

[签名与 TCC 策略](macOS代码签名与TCC身份策略.md) 只作为诊断参考；
其中旧 Universal/正式签名条件不取代本轮企业内测标准。
Actions 不保存真实用户持久 TCC，codesign 成功也不证明本节通过。

## 4. 内置 Harness、模型和会话

不再测试“先安装 Harness 2.1.6 才能用”，也不要求安装独立 Harness 来让模型列表变亮。

1. 无外部 Harness 的新机从 Bot 登录获授权的测试账号。
   主动选择模型/发消息时使用包内 `Resources/ruijie-harness`；
   未登录、额度不足、网络故障说明准确，不读取其他 App 的旧账号。
2. 普通问候、一次无害工具任务、取消和“继续”分别验收；后台桥接不无故打开独立 GUI。
   缺模块必须记录模块名/堆栈、安装器哈希和实际可执行路径，不能靠全局安装 npm 依赖处理。
3. 新建 Bot 的模型/推理档默认值与本次源码配置一致。
   切换到账号实际可用的模型时，Bot 档位映射为该模型允许的值，不因不支持的参数报错。
   不要求测试账号拥有固定的 GPT/Claude/DeepSeek 型号或照抄旧模型排序。
4. 在本版声明支持、且测试账号有权限的模型中抽测工具和图片；
   非视觉模型应准确拒绝/提示，不误派图片后假称成功。缺模型权益写明测试边界。
5. 中文普通回答、进度、英文工具输出后的总结、群组和续聊分别检查；
   用户明确要求英文时按要求，代码、命令和路径不翻译。提示词里有中文规则不等于实际回复通过。
6. 凭据更新或会话恢复后“继续”保留必要上下文，不反复创建空会话、重灌所有历史或重放已取消动作。
7. 记录首次响应、结束时间及所用模型/网络；超时、额度、服务不可达分开归因，
   不以官网响应速度或一轮问候代替稳定性检查。

Harness 包内导出解析 smoke 只证明检查到的导出能在包内解析，不覆盖所有懒加载模块、登录及模型服务。

## 5. 桌面和浏览器分别验，不互相代替

使用临时本地网页作为稳定基线；外站额外验证当前网络可达的网站，不把 Google 不可达当作缺打包依赖。

- 全新 profile 的内置浏览器默认开启；用户主动关闭的已有配置保留。
- 面板先开再让 Bot 操作，以及 Bot/MCP 先用再打开面板，两种顺序都要测。
- 每种顺序完成三轮接管、导航、真实点击/输入、交还、Bot 再操作，正常链路连续观察至少 60 秒原连接。
  页面标题、地址、截图及读取结果对应同一 Bot/session 的实际新页面；旧截图和另一个浏览器不算通过。
- 同一全屏入口能进入/退出，窗口和面板关闭可用；刷新/重连后状态不误判。
- 拒绝连接、不返回响应、取消后换网址均有界恢复，不永久卡“另一窗口占用”；
  两窗口不能同时接管同一 profile。
- 另测受控网络短断、后台切换：按当前实现有界重连，不重放操作、不自动夺回控制；
  不用恢复机制掩盖正常搜索导致的反复断流。
- 开启 Bot 浏览器时，声明支持的搜索、开页、正文和来源 URL 能走同一浏览器；
  无额外搜索 key 的场景不悄悄调用 Firecrawl，不影响其他独立 Harness 会话。

这部分按 [通用回归](04-通用回归与发布门禁.md#4-每版保留的真实行为验收) 留证。
源码 fixture 可用于定位，但不能代替安装包自己的 native runtime 和实际 UI。

## 6. 飞书、插件、UI 与数据

1. 飞书必须从本架构平面 `Contents/Resources/tuantuan-feishu-runtime` 取固定 CLI/Node，
   不借 PATH/Homebrew，不在首次连接时临时 npm 下载替代品。
   当前源码固定 CLI 1.0.93 / Node 24.15.0；不要按截图直接改装到 1.0.96。
2. 测试者本人完成授权，执行一次授权范围内的只读调用、刷新和重启恢复；
   IM 发送仅使用明确同意的测试接收方，不向真实业务群群发。
3. 包内版本执行成功、绿色图标、HTTP 401 都不是全链路通过。
   若遇服务最低版本拒绝、npm 下载超时或 unauthorized，
   保存版本、错误类型及脱敏日志，区分下载/网络/授权，不重复登录或清除账号试运气。
   用户反馈的这类升级问题仍待专项处理，不能继承本次打包 smoke 结论。
4. 其他云插件分别验离线首启→恢复网络/系统代理→点击重试→连接入口→授权→只读调用，
   并覆盖已有连接断网/恢复；不重装、不清缓存、不无故丢连接。
   `CONNECTED_APPS_NETWORK_UNREACHABLE` 是错误归类，不是“没开 VPN”的根因证明。
5. 普通/窄窗口、系统缩放、长中文消息、长工具输出下，主要控件可点、不遮挡，设置关闭可用；
   不把某个旧截图的固定像素或旧菜单位置当成现在必须一致的验收项。
6. 临时 Bot 取消删除、确认删除、离线电脑下删除、归档和恢复均检查；
   其他 Bot/消息不丢，独立远端电脑不随之销毁，可能持续计费的风险说明准确。
7. 如本版声明语音能力，实机测试麦克风/语音权限、输入和拒绝恢复；
   CI 编译 speech helper 通过不算语音功能通过。
8. Local VM/Podman、云沙箱、外部模型等按实际交付承诺测试；
   缺可选服务/账号标环境阻塞或未执行，不要求每台新机安装全套外部工具。

## 7. 覆盖升级与发行身份

仅对获授权的旧安装版测试账户做升级，提前备份/记录测试数据，使用**对应 CPU** 的新 DMG。
旧 Universal 升级到新 thin 包时记录旧/新版本、架构、固定安装路径和签名身份变化；
不能把全新安装通过当成此迁移通过。

检查测试 Bot、历史、设置、电脑选择、模型账号和插件连接保留；
需要重新授权应说明原因，不自动迁移/合并开发版数据。
公司包的 app-update.yml 应为 `AI-Applications-Team/OpenMausBot` 且无 token，
不能用 WYunS 的旧硬编码断言误判公司包。

本企业入口不发布自动更新 feed；验收的是手动安装升级，
不要求 ZIP/latest-mac.yml/Universal 别名，也不为验更新临时发布新 Release。
如本版另外承诺自动更新或正式公证，需另获实现与验收证据，本报告不得代签。

## 8. 报告、放行和续验

四平台正式流程的 Mac 自动证据新增 `macos-arm64-install-lifecycle.json` 与 `macos-x64-install-lifecycle.json`，分别检查最终 DMG 复制安装、替换、文件/链接/权限完整性、安装目录 runtime smoke、删除及隔离数据保留。它们不能代替本文的 Finder、Gatekeeper、真人账号、TCC 和真实历史数据验收，也不能把一种 CPU 的成功填到另一种 CPU。

每项记录“预期、步骤、实际、证据、通过/失败/环境阻塞/未执行”，日志/录像去除账号、邮箱、token 和私人对话。
建议报告头：

```text
候选：仓库 / run / Bot 版本 / 最终源码 SHA / toolkit SHA
安装包：文件名 / CPU / SHA-256 / 大小
机器：CPU / macOS / 实际安装路径 / 签名与公证状态
内置资源：Harness pin / 飞书 pin / browser pin
自动化：各检查结果与日志；不能写成人工已通过
人工：通过数 / 失败数 / 阻塞数 / 未执行数
结论：允许哪一步 / 阻断原因 / 剩余风险 / 负责人
```

核心启动/登录/工具不可用、缺模块、数据损坏/丢失、安全问题、签名不完整、同版权限循环必须阻断。
可选环境缺失、账号权益不足或组织禁止 ad-hoc 安装要准确分类；
能否限制范围交付由负责人明确决定，不写“全部通过”。

非破坏性失败先留证，可继续独立项目；继续会污染数据/结果时停止。
验收者不要悄悄改产品再沿用同一 DMG 哈希；
同一文件仅修正验收器或环境可续验，源码/依赖/配置字节改变须新候选、新哈希和受影响项复测。
